# 生贄将棋

## このリポジトリについて

現在のアプリは **生贄将棋 v1.2.26** です。アプリ本体、改造したやねうら王のソース、学習済み評価関数、定跡、画像・音声、テスト、開発用スクリプトを含みます。Androidの公開用パッケージIDは `net.vipt.ikenie_shogi` です。

公開版に対応するソースは [v1.2.26のリリース](https://github.com/vipt/ikenie-shogi-source/releases/tag/v1.2.26) から入手できます。`ikenie-shogi-1.2.26-source.zip` は、そのAABのビルドで使用した生成済みAndroid設定を含みます。[ビルド手順・配布物の対応関係](docs/SOURCE_DISTRIBUTION.md)と[変更記録](CHANGELOG.md)を参照してください。本アプリはGPL v3以降で配布します。依存ライブラリ・素材の個別の著作権表示は保持しています。

署名鍵・認証情報、端末内の対局データ、生成済みAPK、実験棋譜や検証結果のJSON、ローカル開発ツールはGit管理の対象外です。以下の過去の開発記録には、ローカル生成ファイルへのリンクも含まれます。

```sh
npm ci
npm run typecheck
npm test
```

AndroidのネイティブCPUを含む開発ビルドは、Android SDK・NDK・JDKを設定した環境で `npx expo prebuild --platform android`、`npm run android` の順に実行します。`android/` は設定とプラグインから生成します。既存の配布版へ上書きするには、別途保管している同じ署名鍵が必要です。iOSビルドにはmacOSとXcodeが必要です。ネイティブCPUはExpo Goでは動作しません。

同梱エンジンのライセンスは [COPYING](COPYING)、出典と評価関数の情報は [docs/USI_ENGINE.md](docs/USI_ENGINE.md) を参照してください。プライバシーポリシーは [公開ページ](https://vipt.github.io/ikenie-shogi/privacy.html) とアプリの「設定」から確認できます。以下はこれまでの開発記録です。


## 自駒回収対応エンジン（PC）

やねうら王を改造し、玉は味方の駒を取れず、それ以外の駒は味方を回収できるルールに対応しました。学習済み評価関数 Háo を接続し、241局面・26,411通りの着手を検証済みです。[実行手順](docs/USI_RECOVERY_ENGINE.md)と[検証記録](reports/RECOVERY_ENGINE_VALIDATION.md)を参照してください。現在はスマートフォン版にも組み込んでいます。1.2.8では玉の味方回収にも対応しました（詳細は末尾）。

## 既存エンジン接続（PC・通常ルール）

やねうら王 V9.00 と学習済み評価関数 Háo を導入し、通常ルールでの指し手生成と123手の完走を確認しました。[導入・実行手順](docs/USI_ENGINE.md)と[検証記録](reports/USI_ENGINE_VALIDATION.md)を参照してください。スマートフォン版への接続と回収ルール対応は次の段階です。

味方の駒を回収して、もう一度打てる将棋。iOS・Android共通のReact Native / Expoアプリです。1台で2人対戦、10段階のCPU対戦、先後別に強さを選べるCPU同士の対局に対応しています。

## v1.1.0のCPU改善

CPUを「入門・標準・強め」から選べます。初期設定は「強め」で、旧版の保存データも棋譜を維持して「強め」に移行します。反復深化・αβ探索・静止探索を実装し、駒の取り合いと玉の守りを評価します。強めは1手あたり最大約2.4秒の探索（端末性能により前後）です。

旧CPUとの20局比較は新CPUの20勝・0敗でした。条件と限界は[CPU検証記録](reports/CPU_STRENGTH.md)、参照したGitHubソースとライセンスは[参考資料](docs/ENGINE_REFERENCES.md)に記載しています。

新CPU同士の対局は、100局の予定からユーザーの指示で50局で終了しました。先手20勝（40%）、後手29勝（58%）、320手打ち切りの引き分け1局（2%）。味方の駒の回収は1局平均で先手7.96回、後手6.92回、先後合計14.88回でした。[50局の検証結果](reports/SELF_PLAY_STRONG_50.md)と[全棋譜](reports/self-play-strong-50.json)を保存しています。並列計算を途中で止めた集計であり、終了の早い対局が含まれやすい可能性があります。

片側だけ通常ルール（味方の駒の回収を禁止）とした20局比較では、回収可能側が18勝（90%）、通常側が2勝（10%）、引き分け0局でした。回収可能側は先手で10勝0敗、後手で8勝2敗。同じCPU・32,000ノードの探索上限で先後を交換した10組の実験です。通常側の制限は先読み・詰み判定にも反映し、全20局を棋譜から照合しました。[条件・全棋譜・集計](reports/asymmetric-rules-20.json)。同じCPUの限られた手順での結果であり、人間や別エンジンの勝率を示すものではありません。再実行は `npx tsx scripts/compare-rules.ts`。実験用の `Rules.selfCapture` 設定は省略すると従来どおり両者が回収可能です。

## 遊べる内容

- 味方の駒を取ると自分の持ち駒になります。成駒は元の駒に戻ります。
- 標準ルールでは、**玉は味方の駒を取れず、相手の駒は取れます**。
- 新しい対局の設定で、玉は相手の駒だけ取れる／玉は味方も相手も取れるルールを選べます。どの設定でも玉同士の隣接は禁止です。
- 移動先は緑、味方の駒を回収できるマスは橙で表示します。
- 持ち駒をタップして駒打ち。成りの選択、強制成り、二歩、王手放置、打ち歩詰め、詰み、千日手、連続王手の千日手を判定します。
- 待った、盤面反転、投了、棋譜の表示・共有、対局の端末内自動保存と再開。
- CPU戦では自分の先手・後手を選べます。「待った」は自分の直前の着手まで戻し、後手で遊ぶ場合のCPU初手は残します。
- アカウント・広告・解析送信・アプリ内課金はありません。インストール版の対局は端末内で完結する構成です。

持ち時間、オンライン対戦、持将棋・入玉宣言の自動判定は実装していません。合法手がない側は負け、通常の千日手は引き分けとします。

## 起動

Node.js 22.23.2以上、npm 10.9.9を使用します。依存関係は`package-lock.json`で固定しています。クラウドとnpmのメジャーバージョンを合わせてロックファイルを更新してください。

```sh
npm ci
npm start
```

同じWi-Fiに接続したiPhoneまたはAndroidで、Expo Goを使ってターミナルのQRコードを読み込みます。Expo SDK 58に対応するExpo Goが必要です。物理iPhoneのExpo Goでは、PCのExpo CLIとExpo Goを同じExpoアカウントにログインさせる必要があります。詳細は[Expoの実機起動手順](https://docs.expo.dev/get-started/start-developing/)を参照してください。

このWindows作業環境では `Start-Meguru.ps1` でも起動できます。`npm`がPATHにない場合も、既にインストール済みのNodeとExpoを使います。

```powershell
.\Start-Meguru.ps1
# ブラウザで確認する場合
.\Start-Meguru.ps1 -Web
```

2026年11月14日の作業時点では、開発サーバーはポート8081、静的プレビューは `http://localhost:8082` で起動しています。プロセス終了後は上記コマンドで開発サーバーを再起動してください。

## スマホ版 1.2.4 の表示と音

- 終局ダイアログを廃止し、勝敗・終局理由・手数を盤面上部に表示します。終局した対局の再読み込みでもダイアログを開きません。
- 上部に先手・後手の形勢パーセントとバーを表示します。「設定」から対局を保持したまま非表示にできます。
- 人間・CPUの確定した着手で短い駒音を再生します。選択・待った・読込では鳴らしません。「設定」で消音でき、従来の振動設定とは独立です。
- 音源はオリジナルの合成音です。生成スクリプトは scripts/generate-piece-sound.py。録音・バックグラウンド再生の権限は追加しません。

形勢の計算は、対応する端末内エンジンで現在の局面を100ms解析して得た評価値を先手基準に直し、100 / (1 + exp(-cp / 600)) で換算します。定跡が有効でヒットしたときは定跡の評価値を使います。従来CPUまたは未対応ルールでは従来の静的評価を使います。対局中は1〜99%に制限し、確定した勝敗は100/0、引き分けは50/50と表示します。これは独自ルールの実測勝率に合わせて校正した数値ではなく、有利さの目安です。設定で非表示にすると追加の形勢解析も止めます。

検証: tests/presentation.test.ts、scripts/check-presentation-web.cjs、scripts/validate-mobile-evaluation.cjs。音声APIは [Expo Audio](https://docs.expo.dev/versions/latest/sdk/audio/) を使用しています。

駒音ファイルは約115msの打音の後ろに無音を加え、全体を500msにしています。
Androidで非常に短いPCM音源の初回再生が失われる挙動を避けるためです。
人間・CPUの両着手について、AndroidのAudioTrack再生開始記録と消音時の無再生を検証します。
定跡による350ms間隔の連続着手は scripts/check-fast-book-audio.cjs で検証します。

### 1.2.5: 駒音の音量

右上の「設定」で駒音を0〜100%（5%刻み）に調整でき、「駒音を試す」で試聴できます。設定は対局を変更せず保存されます。初期値・旧データの移行値は75%で、1.2.4と同じ音量です。駒音OFFまたは0%では着手・試聴とも鳴りません。新しい対局の設定でも試聴でき、開始するまで変更は現在の対局に適用されません。端末のメディア音量との組み合わせで実際の音量が決まります。

### 1.2.6: 継続解析と形勢バー

対局画面の表示中は、着手のない間も探索を続け、確定した探索途中の評価を約200ms間隔で反映します。CPU手番ではCPU自身の探索を共用し、二重の探索を起動しません。人の手番・2人対局・CPU対局の一時停止中は継続解析を使います。継続解析では定跡による即時応答を避け、CPU着手時の定跡設定は維持します。形勢バーは450msかけて新しい割合へ移動します（端末の視差効果・アニメーション低減設定を尊重）。

着手、対局変更、設定画面、形勢表示OFF、アプリが非表示になった場合は解析を止め、古い局面の結果を反映しません。終局時は確定結果を表示します。アプリを閉じた後も動くOSのバックグラウンドサービスではありません。従来CPU/Web版も協調的な非同期探索で更新し、盤面操作の時間を確保します。

### 1.2.7: 手数上限と自駒回収数

新しい対局で引き分けの基準手数を1〜4999手に設定できます（初期値320手）。各着手を1手と数え、設定値までは継続、設定値を超えた手で引き分けます。320なら321手目で判定し、その手の詰み・合法手なし・千日手などの終局判定を優先します。手数超過の引き分け後はCPUと解析を停止し、形勢は50%ずつ表示します。

盤面上部に先手・後手別の自駒回収回数を表示します。同じ駒を再び回収すれば、その都度1回と数えます。相手の駒を取った数や持ち駒数は含みません。待った・新しい対局・保存復元に連動します。

旧版の棋譜も全手順を復元してから上限を適用し、決着済みの結果は維持します。旧版で320手を超えて継続していた対局は、棋譜を残して引き分けになります。ネイティブCPUはMaxMovesToDrawを基準手数+1に設定し、探索でも上限超過を引き分けとして扱います。

### 1.2.8: 玉の回収に対応した新CPU

玉が「味方も相手も取れる」場合も、標準・強めではやねうら王＋選択したNNUE評価関数を使います。玉の回収、王手回避、打ち歩詰めの退路判定を拡張しました。回収できる側の指定も維持します。既存の定跡は玉が味方を取れないルール用のため、この設定では使いません。「どの駒も取れない」、入門、従来CPUの明示選択、Web版は従来CPUです。

玉の回収ルールの新CPUは最初の12手だけMultiPV=3で探索し、同じ深さまで読み終えた3候補から最善評価との差50cp以内の手を選びます。候補が揃わない場合や詰みの評価ではエンジンの最善手を使います。13手目以降と継続解析はMultiPV=1です。候補が1つなら同じ手が続く場合もあります。限られた思考時間を3候補に配分するため探索深さが下がることがあり、棋力や勝率が同一とは限りません。

従来CPUにも最初の12手の近接候補選択（歩100点に対し15点以内）を追加しています。ネイティブ連携のmask引数は下位2bitが回収できる側、bit2が玉の回収可否です。フラグ変更時には探索を停止して局面・置換表を初期化します。NNUEの重みは変更していません。

### 1.2.9: CPUの強さを10段階に

新しい対局のCPUレベルを1〜10で選びます。初期設定は7（従来の「強め」と同じ2.4秒・従来CPUの探索予算も同じ）。旧設定は入門→1、標準→5、強め→7に移行し、棋譜を保持します。スマホ版の新しい対局では全レベルでやねうら王を使います。

| レベル | 思考時間上限（秒） | ネイティブ探索深さ上限 |
|---|---:|---:|
| 1 | 0.1 | 1 |
| 2 | 0.2 | 2 |
| 3 | 0.3 | 3 |
| 4 | 0.45 | 4 |
| 5 | 0.7 | 6 |
| 6 | 1.2 | 9 |
| 7 | 2.4 | 時間で制限 |
| 8 | 4 | 時間で制限 |
| 9 | 6.5 | 時間で制限 |
| 10 | 10 | 時間で制限 |

読み込み・描画の時間は上記に含みません。定跡を使う着手は定跡に従います。低レベルから高レベルに順に探索量を増やす設計ですが、勝率・段位・レーティングで校正した10等分ではなく、個別局面の最善手を保証するものでもありません。形勢の継続解析はCPUレベルに関係なく深く読み続けます。深さ制限を切り替える際は置換表を消し、継続解析で読んだ深い結果が低レベルの制限を迂回しないようにしています。

ネイティブ連携の8番目の引数は `{moveLimit, maxDepth}` にまとめています。以前のC APIは深さ制限なしの互換ラッパーとして保持します。Web版と旧保存データの「玉がどの駒も取れない」ルールでは、互換用CPUの探索深さ・ノード数・時間を10段階に設定します。

CPUと評価関数の選択欄はなくし、スマホ版をやねうら王・Háoに固定しました。旧保存データのCPU・評価関数も固定値に移行します。新しい対局の玉ルールは「相手の駒だけ」「味方も相手も取れる」の2択です。過去の「どの駒も取れない」対局は棋譜・終局結果を変えないよう元のルールで復元し、次の新しい対局から「相手の駒だけ」に初期化します。その旧ルールの継続時とWeb版だけは互換用の従来CPUを保持します。追加学習用の資産・検証コードは再現性のため残しています。

### 1.2.10: 先後別CPUレベルと後手での対局

CPU同士の対局では先手・後手それぞれに1〜10のレベルを指定できます。実際の手番のレベルから探索の時間・深さを選び、持ち駒欄とCPU表示・共有棋譜にも先後別レベルを表示します。ひとりで対局する場合のCPUレベルは独立して保持します。旧保存データでは従来の共通レベルを両者に引き継ぎます。

ひとりで対局する場合は自分の先手・後手を選べます。後手なら新規対局開始時に盤を反転し、先手CPUが自動で初手を指します。開始後の手動反転と保存復元も可能です。持ち駒の操作・投了・CPU手番判定は選んだ側に従います。

「待った」は自分の直前の着手まで戻します。CPUの応手待ちなら1手、応手後なら2手戻ります。自分がまだ指していない場合は無効なので、後手対局のCPU初手だけを戻してすぐ再着手されることはありません。CPU同士・ふたり対局では従来どおり1手ずつ戻します。旧保存データの自分の側は先手として復元し、棋譜と盤面方向を保持します。

### 1.2.11: 待った後の「進む」

「待った」の隣の「進む」で、戻した単位ごとに以前の指し手と終局結果を復元できます。ひとり対局では自分とCPUの手をまとめて、CPU同士・ふたり対局では1手ずつ復元します。CPU同士の対局は一時停止したまま確認できます。戻した手順も端末に保存され、別の着手・投了・新しい対局で破棄します。

### 1.2.12: 設定表示と回収数の配置

レベル7の「従来の強め」という補足と、新しい対局の「CPU・評価関数」固定表示を削除しました。自駒回収数は盤の上部から、各プレイヤーの持ち駒数の隣へ移しました。盤面を反転しても、その側の持ち駒と回収数が一緒に表示されます。

### 1.2.13: 先手・後手ごとのプレイヤー設定

対局設定は「先手」「後手」の2欄で、それぞれ人間・CPUとCPUレベルを選びます。両者が人間ならふたり対局、片側だけCPUなら人間対CPU、両者CPUなら観戦になります。選択した側のCPUレベルは人間に切り替えても保持します。旧保存データの対戦相手・先後・レベル・棋譜と進む手順を維持し、次の新しい対局から先後別設定を保存します。人間が後手なら自動で盤を反転します。

形勢表示の先手・後手パーセントの間には、現在の手数と直前の指し手を表示します。待った・進むでも表示局面に追従し、着手前は「開始前」と表示します。形勢を非表示にした場合は、手数を上部に表示します。

### 1.2.14: 先手・後手欄で自駒回収を設定

先手・後手それぞれの欄に「自駒を回収できる」スイッチを配置しました。人間・CPUどちらでも独立して設定できます。保存形式と対局ルールは既存の両者・先手のみ・後手のみ・回収なしに対応し、旧設定を維持します。片側でもOFFにすると非対応の専用定跡はOFFになります。

### 1.2.15: CPU着手のアニメーション

CPUが指すときに約0.55秒で駒が移動元から移動先へ動き、経路も表示します。駒打ちは持ち駒欄から動き、成り・回収数・持ち駒・駒音は着地時に更新します。アニメーション中は次のCPU探索を始めません。待った・新しい対局では古いアニメーションの完了通知を無効にし、一時停止・画面を離れる操作では進行中の着手を確定します。OSの「視差効果を減らす」設定では移動演出を省略します。

### 1.2.16: 玉が味方を回収できるルール用の定跡

両者の「自駒を回収できる」がONの場合、「玉が取れる駒」が「味方も相手も取れる」でも「専用定跡を使う」を選べます。玉のルールに応じて専用ファイルを切り替え、以前の定跡と混用しません。既存の定跡ON/OFF設定は保持します。

新定跡はHáoとスマホ版と同じルール対応エンジンで生成した595局面・626候補手（玉の回収9候補）、初手8種類、24手までです。全局面の合法手・移動後の盤面をアプリ側と照合し、ネイティブエンジンの全局面の定跡採用と240回の初手選択、4対局×60手の定跡終了後の探索移行を検証しました。強さの向上や勝率を測定した結果ではありません。

生成手順は `docs/king-recovery-book.md`、生成・検証の記録は `artifacts/engines/king-recovery-book-v1/book-manifest.json` と `reports/king-book-*.json` に保存しています。

### 1.2.17: 初手別の対局成績に基づく定跡選択

両者回収可の2ルール、初手計20種類を各48局、計960局で測定しました。条件はHáo・1手100ms・深さ上限なし・321手で引き分け。初手を固定し、24手までは現行の定跡を一様に選び、その後は探索します。各対局で探索キャッシュをリセットし、全棋譜を再生検証しています。

最初の各16局で作った頻度案は次の16局で明確な改善を確認できず不採用。次に既存32局から頻度案を固定し、新しい16局で検証しました。玉が味方を取れない定跡は、確認用データの初手選択確率で重み付けした得点率が53.91%→56.13%、差の95%ブートストラップ区間が+0.46～+3.79ポイントとなり採用しました。2九飛・9七桂は各14.81%で選ばれます。12種類すべての初手と後続手順を保持します。

玉も味方を回収できる定跡は、同じ検証で50.00%→53.75%でしたが、差の95%区間が0～+7.29ポイントで事前の採用基準を満たさず、8種類を各12.5%で選ぶ動作を維持しました。数値は固定した初手と現在の後続定跡、100ms探索での条件付き成績です。新旧定跡を直接対戦させた勝率や、全CPUレベルでの棋力差を測ったものではありません。

集計は `reports/opening-outcomes-analysis-v2.json`、初回案の記録は `reports/opening-outcomes-analysis.json`、全棋譜は `artifacts/experiments/opening-outcomes-v2/games.jsonl`。ネイティブでの選択頻度は各ルール1,200回の抽選と全登録局面で検証しています。

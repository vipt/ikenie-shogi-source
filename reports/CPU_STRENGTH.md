# v1.1.0 CPU改善の検証

実施日：2026-11-14。通常将棋の[Aperyとやねうら王の探索ソース](../docs/ENGINE_REFERENCES.md)を参照し、独自ルール用の探索を改善しました。

## 新旧CPUの比較

| 新CPUの手番 | 勝ち | 負け | 引き分け |
| --- | ---: | ---: | ---: |
| 先手 | 10 | 0 | 0 |
| 後手 | 10 | 0 | 0 |
| 合計 | 20 | 0 | 0 |

20局すべて詰みで終了。標準の「玉は味方を取れず、相手を取れる」ルールを使用しました。全棋譜・局ごとの探索量は[cpu-comparison.json](cpu-comparison.json)に保存しています。

- 新CPU：最大32,000ノード、最大深度7。比較を再現可能にするため、時間制限は無効。
- 旧CPU：v1.0.1の2手先、候補幅14、評価の揺らぎ6。コードは`src/game/cpu-legacy.ts`に保存。
- 10組で先後を入れ替え、組ごとに同じ乱数seedを旧CPUに使用。全局を初期局面から開始。
- 最大240手で打ち切り引き分け（今回は打ち切りなし）。
- 新CPUが完了した通常探索の深さは平均2.66手。捕獲・成り・王手回避に対する追加探索は別。最大7手を毎回読んだ結果ではありません。

この結果は旧版との比較です。少数かつ同じ初期局面からの対戦で、未知の相手に対する勝率、段級位、通常将棋エンジンと同等の強さを証明するものではありません。実アプリには2.4秒の時間制限もあり、端末性能や局面によって探索量が減ります。

探索量を8,000ノードに減らした補助比較でも、新CPUは8勝・0敗（先手4局、後手4局）でした。平均完了深度は2.08手。[補助比較の全棋譜](cpu-comparison-low-budget.json)。これは端末性能の実測ではなく、探索量が少ない場合の検証です。

```sh
npx tsx scripts/compare-cpu.ts --games 20 --workers 4 --nodes 32000
```

## 戦術・操作の回帰検証

- 駒得より1手詰めの金打ちを優先。
- 旧CPUが飛車を取って次の金打ちで詰まされる局面で、新CPUが詰みを防ぐ。
- 王手時に合法な回避手を選ぶ。
- 探索のノード制限到達時も合法手を返し、入力局面を変更しない。
- 非同期探索中にキャンセルすると着手を返さない。
- 旧保存形式を読み込むと棋譜を維持して「強め」へ移行。
- 既存のルールテストを含む37件が成功。型チェック成功。
- Chromeで「強め」の選択・保存、CPU応手、思考中の「待った」後に古い探索結果が反映されないことを確認。

## 先後の勝率について

以前の1,000局（先手472勝・後手519勝・引き分け9局）は**旧CPU同士**の実験です。新旧CPUの20局比較は棋力改善の検証です。別途実施した[新CPU同士50局](SELF_PLAY_STRONG_50.md)は先手20勝・後手29勝・引き分け1局でした。100局の予定をユーザーの指示で途中終了した集計で、先後の公平性を断定するものではありません。旧実験は`self-play.ts`を旧CPUに固定して再現できるように保持しています。

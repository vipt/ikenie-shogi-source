# めぐる将棋：CPU同士の1,000局検証

実施日：2026年11月14日（日本時間）。v1.0.1の入門CPU（現在の`cpu-legacy.ts`）と実際のルールエンジンで対戦させた結果です。v1.1.0で追加した「標準」「強め」同士の先後バランスを示すものではありません。

## 結果

| 結果 | 局数 | 全対局に占める割合 |
| --- | ---: | ---: |
| 先手勝ち | 472 | 47.2% |
| 後手勝ち | 519 | 51.9% |
| 引き分け | 9 | 0.9% |

後手が47勝多く、勝率の差は4.7ポイントでした。ただし、この結果だけでは後手が有利だとは断定できません。

- 決着した991局に限った先手勝率：47.63%。
- 引き分けを0.5勝とした先手の得点率：47.65%。
- 同じ乱数シードの対局ペアを単位とするブートストラップ95%区間：**44.8%〜50.5%**。
- この区間は50%を含みます。「五分五分と矛盾しない」結果ですが、「完全に公平」「±5ポイント以内」と証明できたわけではありません。
- 平均手数：91.05手（片側の着手を1手と数える）。
- 味方の駒の回収：平均0.506回／局。回収が一度以上あったのは305局、最多10回。
- 全1,000局の棋譜は互いに異なりました。

## 対戦条件

- 通常の将棋の初期配置。味方の駒を取ると、自分の持ち駒になる。
- **玉は味方の駒を取れず、相手の駒は取れる。** どちらの玉も取ることはできない。
- 成駒の回収・捕獲時は、成る前の駒に戻す。
- 二歩、打ち歩詰め、王手放置、行き所のない駒を禁止。成り・強制成りを判定。
- 4回の同一局面で千日手。連続王手を続けた側は負け。
- 320手で未決着の場合は、実験上の引き分けとして別記。アプリの対局にはこの手数上限を設けていない。
- 同一の2手先探索CPU（各局面の候補上位14手、駒の価値・成り・配置・王手を評価）。
- 同程度の候補を選ぶ際に最大±3評価点の乱数を加える。歩の価値は100点。
- 基準シード20261114。500組それぞれで2つのシードを用意し、先手と後手に割り当てるシードを入れ替えて2局ずつ対戦。
- CPU評価・合法手が盤面の180度回転と先後交換に対して対称になることを自動テスト。
- 95%区間は500組のペアを10,000回再標本化して算出。JSON内のWilson区間は、決着局を独立と仮定した参考値。

終局の内訳は、詰み982局、連続王手の千日手9局、通常の千日手6局、320手到達3局です。

## 読み取りの限界

このCPUは入門用です。味方の駒を回収して数手後に打ち直すような長い構想は読み切れず、実際に約7割の対局では一度も回収しませんでした。結果はこのCPU・評価関数・初期配置・手数上限での傾向であり、強いAIや人間の対局にもそのまま当てはまるとはいえません。

初回の200局（先手96勝、後手103勝、引き分け1局）は、この1,000局の先頭200局です。別の追加標本として合算していません。

## 再現

```sh
npm ci
npm run selfplay -- --games 1000 --max-plies 320 --workers 4 --seed 20261114 --out reports/self-play-1000.json
```

`self-play-1000.json` に全棋譜、各局の乱数シード、勝者、終局理由、手数、回収数、集計値を保存しています。途中ファイルは `.gitignore` の対象です。局数は偶数で指定します。

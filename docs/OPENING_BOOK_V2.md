# 専用定跡 v2

両者が味方の駒を回収でき、玉は味方を取れないルール専用。初手1種類だったv1を拡充し、Háoで調べた12種類の初手と応手を収録した。

- 登録指し手: 2840

- 深さ: 初期配置から最大24手目
- 評価関数: Háo (2023-05-08)、SHA256 1141d275bceec911156801f27303dc9ff5beb24f4f59144cc069306c59e80782
- 定跡SHA256: 58d96ea50fdf68d3d6fbd80386e3dbc857dabcffafd20a3f887d877865dbf82c

## 探索と選択

初期局面をMultiPV 12・15秒で探索し、候補を指した局面をそれぞれ4秒で再評価した。初手は最良値との差150cp以内。後手の初回応手は最大3手、3・4手目は最大2手、それ以降は1手を登録。初手以外の分岐は評価差100cp以内。各局面の探索は序盤1.8秒、それ以降0.6秒・MultiPV 3。評価値が確定していない場合は3秒で再探索する。

前回の定跡なし対局で現れた応手や調査時の読み筋も出発点に含めた。すべての登録手・予想応手をTypeScript側のルールで再生し、途中で定跡が途切れないことを確認。予想応手は検索中の仮のPVを転記せず、実際に収録した次局面の手を参照する。

BookEvalDiff=150、NarrowBook=false、ConsiderBookMoveCount=false、BookIgnoreRate=0。評価値を同点に改ざんせず、条件内の登録候補から等確率で抽選する。旧v1は変更せず artifacts/engines/recovery-v1 に保存。

## 検証

- PCで初期局面から240回抽選し、12候補すべてが選ばれた。
- 全初手から24手までを定跡だけで進め、合法性と定跡ヒットを確認。
- 旧定跡と40局: 新定跡 19勝、旧定跡 21勝、引き分け 0。
- 条件: 両者Háo、1手100ms、1スレッド・64MiB、先後各20局、各側別エンジン・各局新規プロセス。
- 新定跡の平均ヒット数: 2.925手／局（新定跡を使う側のみ）。

これは序盤の多様性を増やす変更であり、40局の結果だけで棋力向上は断定できない。通常将棋で学習した評価関数による推定値を使っている。評価値は勝率を意味しない。MultiPVは隣接する深さの候補を含むことがあり、順位は絶対ではない。

## スマホ版

1.2.3に同梱。「専用定跡を使う」をオンにすると利用できる。Háo／追加学習版のどちらでも使え、評価関数を自動変更しない。両者回収＋玉は相手の駒だけ取れる設定のみ有効。定跡オフの既存設定は維持する。

再生成: scripts/research-recovery-openings.ts → scripts/build-recovery-book-v2.ts → scripts/validate-recovery-book-v2.ts → scripts/update-mobile-book.cjs。Android検証は scripts/validate-mobile-book.cjs と scripts/check-mobile-book.cjs。

Androidネイティブ版でも全2,715局面の定跡ヒットを確認しました。
初期局面から240回抽選して全12候補が選ばれ、8MiB以上の探索スレッドスタックも確認済みです。
結果は reports/recovery-book-v2-android-validation.json に保存しています。

現在の生成コマンドは book:research → book:build → book:validate → book:mobile です。
旧生成処理は book:build:v1 として残しています。
scripts/selfplay-sente-book.ts と startTrainedRecoveryEngine は過去実験の再現用としてv1を参照します。
v2の比較には scripts/validate-recovery-book-v2.ts を使用してください。
